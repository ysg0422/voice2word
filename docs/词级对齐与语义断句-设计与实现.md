# 词级对齐与语义断句：设计与实现

> 状态：**本轮已实现「拆句时刻用真实词边界 + 句末标点优先」**（2026-10-23）；
> 模型级强制对齐（wav2vec2 / CTC）未做，方案见第 5 节。

---

## 1. 现状（改之前）

| 环节 | 实现 | 问题 |
|---|---|---|
| 词级时间 | Whisper token → `WordTiming`（`word_timings_from_tokens`），VAD 生效时用 `align_words_to_segment` 线性映射回段窗口 | 时间来自模型，本身可用；问题在下游怎么用它 |
| 长句拆分 | `split_segment_recursive`：按标点就近选切点，**时间轴一律按字数比例插值** | 语速不均（强调、停顿、拖音）时切点落在词中间 → 拆分后的逐词高亮/卡拉 OK 错位 |
| 切点选择 | `split_index_at_ratio`：25%~75% 区间内取「离目标字数最近」的标点 | 逗号与句号等价；括号/引号内部的标点也参与竞争，会把「（补充说明）」劈开 |

## 2. 本轮改动一：拆句时刻取真实词边界

`split_time_from_words(words, cut_chars, start, end) -> Option<f64>`：

- 累计每个词的非空白字符数，找到「累计字数最接近文本切点」的词；
- 取该词的 `end` 作为切分时刻——这是**测出来的**边界，不是插值；
- 返回 `None`（回退到 `start + 时长 × 字数比例`）的条件：词不足两个、切点在段首、
  所有候选词时间非有限或贴着段首/段尾。

为什么用「累计字数最近」而不是「时间中点最近」：文本是按字数切的，词与字数的对应
关系才是两者的共同坐标；按时间找会把「字少的快词」错配给左半。

**收益**（`split_time_uses_measured_word_boundary`）：10 秒 11 个字、语速不均时，
比例插值给 5.45s，词边界给 4.0s——差 1.45s，足以让一整句的逐词高亮错位。

## 3. 本轮改动二：断句的语义优先

### 3.1 标点强度

`split_punct_strength`：句末（`。！？…` / `. ! ?`）= 3，分号/冒号 = 2，逗号/顿号 = 1。
打分时把强度折算成**距离折扣**（每级 -2 字符）：

```
score = |切点字数 - 目标字数| - (强度 - 1) × 2
```

于是「我们出发吧，天气不错。还要赶路」里，逗号只近 1 个字符、句号远 4 个字符，
句号仍胜出（4 - 4 = 0 < 1）——不会为了 1 个字符的接近把完整的一句话拆成两行。

### 3.2 括号/引号保护

`inside_pairs` 用配对深度（`（）()【】[]《》「」『』`）与中文引号状态判断，落在
内部的标点直接跳过。宁可切在更远的逗号上，也不把补充说明/引语从中间劈开。

## 4. 测试

| 测试 | 钉住的行为 |
|---|---|
| `split_time_uses_measured_word_boundary` | 有词时间时切点 = 词边界（4.0s ≠ 5.45s），词分片数正确 |
| `split_time_falls_back_to_ratio_without_words` | 无词时间时回退字数比例，不 panic |
| `split_prefers_sentence_final_punctuation` | 句末标点以 4 字符折扣胜出 |
| `split_skips_punctuation_inside_brackets` | 括号内逗号被跳过，退到括号外 |
| 既有 `split_long_segments_*` 6 个用例 | 词守恒、顺序、段区间、`locked` 与语言包继承均不变 |

## 5. 明确未做：模型级强制对齐

真·词级强制对齐（WhisperX 的 wav2vec2 / 中文 CTC）需要：

1. 一个对齐模型（英文 wav2vec2 ~360MB；中文需 Paraformer/CTC 系，另有大小的模型）；
2. `tools/align_runner.py`（onnxruntime 推理 + Viterbi/CTC 对齐）；
3. `engines::AlignEngine`（进程契约与其它 runner 一致：双端抽干、有界等待、取消）；
4. 模型下载项与配置路径；
5. 管线阶段：转写后按句对齐，把 `WordTiming` 从「token 近似」升级为「声学对齐」。

本轮不动它，原因：模型体积与下载成本高，且现有 Whisper token 时间在多数素材上
已够用；先修「拿到词时间却没用对」的问题，收益/成本比更高。

## 6. 后续可选（按价值排序）

1. **静音吸附**：用 VAD 的静音区间把相邻句的边界吸到停顿中点（需要把 VAD 区间
   从 whisper 内部暴露出来，目前没有这条数据通路）；
2. **对齐质量指标**：`sum(词时长) / 句时长` 覆盖率进质检，低于阈值的句子标「词级
   时间可疑」，引导用户人工核对；
3. 上述模型级对齐（真正做词级 OCR 之外的「听清每个字」）。
