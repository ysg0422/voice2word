## 第五梯队：AMD 显卡转写加速专项（你的机器是 AMD）

> 现状：whisper.cpp 走 Vulkan（`-fa` Flash Attention），但 **SenseVoice 与 CT-Punc 两个 ONNX 引擎硬编码 `provider="cpu"`**，完全没吃 GPU；FFmpeg 全 CPU 软解（`-threads 0`，无 `-hwaccel`）；`HardwareProfile` 只区分 `Gpu/CpuSoftware`，没有厂商维度。以下按收益排序。

### P0-A1 SenseVoice / CT-Punc 上 DirectML `[~]`
- **落点**：`tools/sensevoice_runner.py:177` 与 `tools/punc_runner.py:28` 硬编码 `provider="cpu"`
- **内容**：sherpa-onnx 支持 `DmlExecutionProvider`，Windows + AMD 免 ROCm 直接吃显卡。改为「有 DML 就用 DML、否则回落 CPU」，并加 `--provider` 参数让 Rust 侧可控。
- **预期**：SenseVoice 是目前最快档位，INT8 模型上 DML 可再降延迟；CT-Punc 毫秒级也能进一步压。
- **验收**：同素材对照 CPU vs DML 出字延迟下降，且精度不变。
- **进度 2026-10-06**：`--provider` 参数已全链路打通（两个 runner + Rust 引擎 + `GpuConfig.onnx_provider` 配置项）。⚠️ 实测本机 sherpa-onnx 1.13.7 绑定的 onnxruntime 是 CPU-only 版（stderr 打 "Unsupported string: dml. Fallback to cpu"），`dml` 当前静默回落 cpu、零回归。**真正吃到 GPU 需把 Python 的 sherpa-onnx 换成 DirectML 变体**（`pip install onnxruntime-directml` + 对应 sherpa-onnx 构建），这是下一步。

### P0-A2 whisper.cpp 后端基准选型 `[x]`
- **落点**：`engines/whisper.rs` 的 `-fa` / `-ng` 分支、`config.toml [paths].whisper_cli`
- **内容**：Vulkan 在 AMD 上非最优。做一轮基准：
  1. 现役 Vulkan（`-fa`）作为基线；
  2. 试 `-ngl` 层数调节与 `--no-fft` 等 flag；
  3. 评估 whisper.cpp **DirectML 后端**或 **HIP/ROCm 后端**的自行编译版（`model_custom_build` 已有「自编译构建」识别，直接复用下载/标注逻辑）。
- **验收**：产出 `docs/` 下一份基准表，选定 AMD 最优后端并写进 README 推荐。 ✅ 2026-10-06 完成：新增 `scripts/build_whisper_msvc_vulkan.bat`（MSVC + Vulkan 一键编译并部署），并实测选定 **MSVC + Vulkan** 为 AMD 核显最优后端。同素材 105s 切片实测：官方 CPU 包 13.21s → MSVC+Vulkan(GPU) **7.33s（1.80×）**，转写结果逐段一致（52 段）。**关键收益是「换了编译工具链」**：MinGW Vulkan 版曾因缺 libgcc/libstdc++/libgomp 以 0xC0000139 秒退，MSVC 版只依赖系统自带的 VC++ 运行库。详见 `docs/Whisper后端基准-MSVC-Vulkan.md`。

### P0-A3 FFmpeg 硬解（hwaccel）`[ ]`
- **落点**：`engines/ffmpeg.rs`（当前 `-threads 0` 全软解，无任何 `-hwaccel`）
- **内容**：转写抽音频本身 CPU 占用不高，但**视频预览 / 代理生成 / 波形提取**全走软解会抢 CPU 给转写。AMD 在 Windows 上 `-hwaccel d3d11va`（或 `d3d12va`）支持最好，优先给预览链路上硬解，抽音频保持软解不折腾。
- **验收**：播放 4K/HEVC 预览时 CPU 明显下降，转写并行时桌面不卡。

### P0-A4 厂商识别（Vendor 枚举）`[x]`
- **落点**：`engines/media_pipeline.rs` 的 `HardwareProfile`（现只有 `backend` + `is_discrete`，无厂商）
- **内容**：从 `adapter_name`（如 `Radeon` / `NVIDIA` / `Intel`）归类出 `Vendor` 枚举，让 GPU 策略按厂商分流（AMD→DML/硬解、NVIDIA→可考虑 CUDA/`cuvid`）。
- **验收**：启动日志打印厂商，后续所有「按厂商选后端」的逻辑有统一依据。 ✅ 2026-10-06 完成：`Vendor` 枚举 + `from_adapter_name` 模糊归类（AMD/NVIDIA/Intel/Other），`HardwareProfile` 加 `vendor: Option<Vendor>` 字段并导出，`main.rs` 启动日志打印厂商，附 3 个单测。`cargo test --lib` 247 passed/0 failed。

### P0-A5 GPU ETA 分厂商校准 `[x]`
- **落点**：`app/state.rs` 的 `WhisperModelTier::estimate_seconds`（GPU 统一乘 `0.28`，未按厂商/模型细分）
- **内容**：AMD 实测各档位（Base/Small/Turbo）的 GPU 实时倍率，替换掉统一 `0.28` 系数，避免「预计 2 分钟实际 8 分钟」的误导（代码里已有 SenseVoice 误标 5.5 倍的前车之鉴）。
- **验收**：ETA 与实际误差 <30%。 ✅ 2026-10-06 完成：新增 `WhisperModelTier::gpu_speedup_ratio()`，按档位实测标定 GPU/CPU 比值（本机 AMD 核显 300s 样片：Fast 0.585、Balanced 0.412、Turbo 0.199）。旧统一 `0.28` 会把 Turbo 高估 ~40%、把 Base 低估 ~30%。新增单测 `gpu_speedup_is_tier_dependent` 锁住「加速比随模型变大而增大」。
