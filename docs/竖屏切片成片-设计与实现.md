# 竖屏切片成片：设计与实现

> 状态：已实现（2026-10-23）。入口：「统计与导出 → 智能切片」卡里的
> **「竖屏成片 9:16」** 按钮。

---

## 1. 目标

智能切片已经能挑出高光片段并原样剪出来，但「原样剪出来」只是素材，不是能发布的作品。
竖屏成片补上最后一公里：**9:16 画面 + 烧录字幕**，导出即可上传。

## 2. 画面处理

```
scale=1080:1920:force_original_aspect_ratio=increase,crop=1080:1920
```

- `force_original_aspect_ratio=increase` 先等比放大到**覆盖**画布；
- `crop` 居中裁切到目标比例。

这是竖屏二创的通行做法。为什么不做人脸跟随：需要检测模型与跟踪算法，成本远高于
本轮目标；居中裁切对「人物在画面中央」的口播/访谈素材已经够用（后续可加「主体
检测 + 动态 crop 起点」）。

## 3. 字幕为什么必须重写

烧录的字幕要按**切片相对时间轴**排：切片从 12:30 开始，字幕第一句也得从 0 开始，
否则整条切片的字幕全都不显示（时间戳超出片长）。因此每条切片单独生成一份 ASS：

1. 选与切片区间有交集的句子；
2. 每句 `start/end` 平移 `-cand.start`，并夹到 `[0, 切片时长]`（夹取后保证不短于
   `MIN_EDIT_DUR`，避免 0 长度事件）；
3. 用用户当前的字幕样式（`SubtitleStyleConfig`）与导出模式（原文/译文/双语）写出；
4. 临时 ASS 用 `TempPathGuard` 管生命周期，导出结束即删。

ASS 头是 `PlayRes 1920×1080`，而画布是 1080×1920：libass 按高度比缩放字号、按宽度
比缩放横向位置，居中对齐（`alignment=2`）在两种比例下都锚在画面中线，实测渲染正常
（见验证段）。

## 4. 编码与出片

复用切片导出的参数取向：`libx264 + preset veryfast + crf 20 + yuv420p + aac 192k
+ +faststart`（`+faststart` 让 moov 前置，网页/移动端可边下边播）。

时间定位用**输入侧** `-ss`（关键帧跳跃，长素材快一个量级）配 `-t` 指定时长——
不用 `-to`，避免「输入侧 `-ss` + 输出侧 `-to`」的基准混淆。

## 5. 失败处理

一条切片失败不影响其余（与切片导出同口径），提示行给出成功/失败条数与首条错误。
字幕区间内没有任何句子时，该条直接记失败并跳过（不产出一条无字幕的成片）。

## 6. 验证（真机）

素材：320×240 / 6s 测试片 + 一条 ASS（`竖屏成片字幕测试`）。

```
ffmpeg -ss 0.5 -t 4 -i test.mp4 \
  -vf "scale=1080:1920:force_original_aspect_ratio=increase,crop=1080:1920,subtitles=filename='clip.ass'" \
  -c:v libx264 -preset veryfast -crf 20 -pix_fmt yuv420p -c:a aac -b:a 192k \
  -movflags +faststart vertical.mp4
```

结果：`1080×1920`、`h264`、`4.04s`；抽帧确认字幕「竖屏成片字幕测试」已烧在画面下方
居中位置（1080×1920 全画幅，无黑边、无拉伸）。
